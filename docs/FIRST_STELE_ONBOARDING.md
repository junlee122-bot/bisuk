# 첫 기준 비석 온보딩 — 충주 고구려비 실제 데이터 연결 방법

데모 환경에서는 충주 탭에 가상 메시(DEMO-A)가 열린다. 실제 공식 3D 데이터를
연결하려면 아래 절차를 따른다. **앱은 어떤 파일도 자동으로 내려받지 않는다.**

## 절차

1. 워크스페이스에서 `충주 고구려비` 탭 → `Source Card · 자산` 화면을 연다.
2. `국가유산청 국가유산 디지털 서비스` Source Card의 링크를 브라우저에서 직접 연다.
3. 해당 페이지에서 **자산별 공공누리 유형과 이용 조건을 확인**한다.
4. 조건을 확인한 파일(PLY/STL/ASC)을 본인 계정으로 직접 내려받는다.
5. `자료 등록` 슬롯(모든 탭에서 연구원 이상)에서 파일을 선택하고 **사용 목적**을 기록한 뒤 등록한다.
   사진·탁본(JPG·PNG·WebP·TIFF), 3D(PLY·STL·OBJ·GLB·E57·LAS), RTI, PDF를 받으며, 대용량은 스트리밍으로 저장한다.
   - 서버가 sha256 체크섬을 계산하고 원본을 불변 저장한다.
   - PLY/STL/ASC 검사기가 정점·삼각형·점 수, 법선/색상 유무, 경계상자,
     단위 추정(확인 필요 표시)을 담은 품질 보고서를 생성한다.
   - 자산은 `VERIFY_REQUIRED` 상태로 시작한다.
6. **PI**가 확인한 공공누리 유형을 라이선스 폼에 입력하고 저장한다(확인자는 로그인 계정으로 자동 기록).
   - 확인 전: 내부 분석 가능, 외부 공개 내보내기 차단.
   - 확인 후: 허용 범위 내 내보내기 가능 (manifest에 라이선스 명시).

7. 자산 카드에서 **단위를 확정**한다 (3D는 mm/cm/m, 사진·탁본은 작업대 이미지 뷰어의 `축척 막대`로 두 점 + 실제 길이).
   단위가 확정되기 전에는 어떤 측정값도 mm로 표시하지 않는다.
8. 출판 판독문이 있으면 `비석 관리 → 판독문 가져오기`로 붙여 넣어 면·행·자 셀과 출판본 판독을 만든다.
9. 작업대 `사진·탁본` 뷰어에서 셀 영역을 지정하고, **원본에 보이는 획만** 추적한다
   (보이지 않는 획·균열을 지어내지 않는다 — 마모로 일부만 보이는 획은 '마모 표시'로 구분).
10. 판독은 `판독 (판독자별)` 패널에서 제안하고, PI가 채택한다. 자동 분석 결과는 판독안으로만 넘길 수 있다.

## 등록 후 처리 파이프라인 (P0 → P1)

| 단계 (PRD §3 탭1) | P0 | P1 |
|---|---|---|
| 원본 체크섬 계산 | ✅ sha256 | |
| 원본 변경 불가 저장 | ✅ `wx` 쓰기 | 오브젝트 스토리지 이전 |
| 좌표계 검사·단위 추정 | ✅ 경계상자 기반 추정 + 사용자 확인 요구 | |
| 메시 정리·GLB 변환·LOD | — | Open3D/Trimesh 워커 |
| 법선·곡률·음영 지도 | — (가상 메시는 절차 생성으로 시연) | Surface Analysis 엔진 |
| 문자 셀 제안·기존 판독 좌표 연결 | — (가상 셀로 흐름 시연) | Glyph Segmentation |

## 주의

- 실제 파일이 등록되기 전까지 3D 작업대에는 가상 메시가 열리며,
  화면에 "실제 충주 고구려비 데이터 아님"이 항상 표시된다.
- 실제 3D 원본(PLY·STL·OBJ·GLB, 250 MiB 이하)은 `3D 실측` 뷰어에서 원본 그대로 열어 거리·단면 프로파일을 잴 수 있다.
  더 큰 원본은 `3D 품질` 패널에서 증거용 파생본(LOD)을 만든 뒤 본다. E57·LAS는 저장·보존만 하고 브라우저 표시는 하지 않는다.
- 문자 셀 자동 분할(Glyph Segmentation)은 아직 없다 — 셀 영역은 판독문 가져오기 격자 또는 사람이 지정한다.
